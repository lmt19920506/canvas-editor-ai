## 控制点尺寸改为屏幕恒定 18px（解决上文 line29 的遗留取舍）
- 需求：8 个控制点不随画布缩放变化，屏幕上始终 18px
- `config/editor.ts`：`HANDLE_SIZE = 8` → `HANDLE_SCREEN_SIZE = 18`，语义由「设计坐标单位」改为「屏幕 px」
- `utils/selection.ts`：新增 `pxInDesign(screenPx, displayScale) = screenPx / scale` 与 `handleSizeInDesign(scale)`；`handleHitRadius` 由 `size/2 + 6` 改为比例式 `size * 1.25`（scale=1 时与原值 10 等价，且屏幕手感不随缩放变化）
- `SelectionOverlay.vue`：新增 `scale` prop（父级传入画布显示缩放比）；`size = pxInDesign(18, scale)`；虚线框 1px、控制点描边 1.5px、圆角 1px 同步做 1/scale 换算，否则缩小后线会细到看不见；控制点定位简化为 `left = p.x - el.x` + `margin -size/2`（size/2 与选中框外扩 pad 相消）
- `useCanvasEditor.ts`：新增 `displayScale()`（= canvas DOM 宽 / 设计宽，与 toDesignPoint 同源，未布局时回退 1）；`handleAt` 用 `handleHitRadius(handleSizeInDesign(displayScale()))`，保证「看到的点」＝「能点到的点」
- `CanvasArea.vue`：`<SelectionOverlay :el="..." :scale="scale" />`
- 关键原则：凡渲染在 `transform: scale` 图层内的「屏幕恒定尺寸」，都要 1/scale 反向换算；渲染与命中必须用同一换算
- typecheck / build 通过

## 修正控制点定位（上一轮的 margin 简化引入的 bug）
- 现象：8 个控制点整体左上偏移约 9px，不在虚线框的角/边中点上
- 根因一：绝对定位子元素的基准是父元素 **padding box**（border-box 下 = 边框盒内缩一个边框宽 bw）；
  上一轮把 `- size/2 + pad` 换成 `margin: -s/2`，漏掉 pad 抵消项 → 偏移 (s/2 - bw)
- 根因二：`handlePoints` 返回的是**元素角点**，而控制点中心应落在**选中框（元素外扩 pad）的角/边中点上**，两者也差一个 pad
- 修正：`handlePoints` 改为返回外扩矩形的 8 个点（中心即虚线框上的点）；组件定位用
  `left = p.x - el.x + pad - bw - half`（pad 与 half 恒等相消，保留写全以说明推导）
- 视觉结果：虚线正好穿过每个控制点中心；因 pad = 半径，控制点整体位于元素轮廓之外，不遮挡内容
- 已用脚本校验：scale = 1 / 0.42 / 0.2 下控制点中心与选中框角点偏差均为 0，屏幕边长恒为 18px
- 教训：**CSS 绝对定位的基准是 padding box 而非 border box**，算子元素偏移时不要漏掉边框宽度
- typecheck / build 通过
